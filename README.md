# azionapi-python-sdk

Official Azion SDK for the Python programming language.

The repository contains one Python package per Azion API product. Every
package is generated by [OpenAPI Generator](https://openapi-generator.tech)
from the product's OpenAPI document and is self-contained: it has its own
`setup.py`, `requirements.txt`, API reference (`docs/`) and README.

## Requirements

- Python 3.7 or later (3.8 or later for `edgeapplications` and `edgefunctions`)
- The dependencies listed in the package's `requirements.txt`

The packages were produced by different generator versions, so their
requirements differ (for example `pydantic` 1.x or 2.x). Install each
package in an environment that satisfies its own `requirements.txt`.

## Installation

Install a package straight from this repository with pip, pointing to its
directory. Pin a release tag to get a reproducible build:

```sh
pip install "git+https://github.com/aziontech/azionapi-python-sdk.git@v0.83.0#subdirectory=personal_tokens"
```

## Usage

All packages follow the same pattern: build a `Configuration`, set the API
token, open an `ApiClient` and instantiate the API class. For example, with
`personal_tokens`:

```python
import personal_tokens
from personal_tokens.apis.tags import personal_token_api

configuration = personal_tokens.Configuration(host="https://api.azionapi.net")
configuration.api_key["tokenAuth"] = "YOUR_API_TOKEN"
configuration.api_key_prefix["tokenAuth"] = "Token"

with personal_tokens.ApiClient(configuration) as api_client:
    api = personal_token_api.PersonalTokenApi(api_client)
    response = api.list_personal_token()
    print(response.body)
```

Packages built with the pydantic generators expose their API classes under
`<package>.api` instead of `<package>.apis.tags`; see each package README.

## Development

The package directories are generated code. They are updated by automated
`generated-sdk` pull requests ("Auto-Generated SDK" commits), so do not edit
them by hand: changes belong in the OpenAPI documents or generator settings.
Repository-level files (tests, workflows, documentation) are maintained here.

Run the functional tests (Node.js 22 and Python 3.11 required):

```sh
cd tests/vitest
npm ci
npm test
```

The suite builds one virtualenv per distinct `requirements.txt`, imports
every package, checks that each endpoint documented in the package README
exists, and calls one endpoint per generator flavour against a local HTTP
double to verify routing, token authentication and response deserialization.

Linting: `ruff check .` (configuration in `ruff.toml`) and ShellCheck on
the `git_push.sh` scripts.
